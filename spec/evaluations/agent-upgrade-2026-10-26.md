## RAG 真实模型

60 份合成资料、100 个标注问题；真实 ES/MinIO 和硅基流动调用。文本使用 `deepseek-ai/DeepSeek-V4-Flash`，Embedding 使用 `BAAI/bge-m3`（1024 维）；另验证真实 `BAAI/bge-reranker-v2-m3` 计量。

| 指标 | 实测 |
| --- | ---: |
| 任务完成 | 100/100 |
| Recall@20 | 1.0（90 道有标注来源的问题） |
| 可回答题匹配预期来源且包含预期事实 | 78/80（97.5%）；2 题保守拒答 |
| 无答案题标记证据不足 | 10/10；其中 2 题仍引用相关资料，不等同于给出答案 |
| 冲突题引用两个来源并保留双方事实 | 10/10 |
| P50 / P95 | 3.062 / 12.077 秒（双并发测试） |
| 模型调用 / token | 261 / 187,327 |
| unknown 用量 | 0 |
| 费用 | 未配置价格，保持未知 |

测试使用生产同样的心跳续租；检索召回评估额外请求 top20，问答仍取 6 条证据。来源匹配和事实字符串检查为自动指标，不能替代人工引用正确率或真实业务集质量。原始结果见 [RAG JSON](agent-rag-2026-10-26.json)；可复现入口为 `backend/tests/agents/live_acceptance.py`，需显式运行，默认单元测试不产生付费请求。

## 音乐资料切分与检索修复

用户实际上传的 8 篇音乐 Markdown 暴露了合成测试未覆盖的问题：按空行逐段切分，使“25 分钟专注歌单”的标题、表格和说明分离。使用原任务保存的查询向量复现后，融合排名中标题为第 1、说明为第 3、完整表格为第 24，另一篇中的完整安排为第 10；原问答只接收前 6 段。复现请求指纹与原模型请求相同，确认答案没有传入模型。

修复为同章节连续段落合并、章节前缀参与检索、6 段主证据补齐同文档/版本/章节的相邻片段，总证据不超过 9,000 tokens，最多引用 6 段。以下结果使用真实 ES/MinIO、原硅基流动模型且未开启 rerank。

| 验证 | 实测结果 |
| --- | --- |
| 回归 | 40 项通过：原 Agent 集成测试 31 项 + 新知识库专项 9 项；未重新宣称全量回归 |
| 旧索引兼容 | 原问题在 V1 文档上正确回答 3 / 19 / 3 分钟，并引用原表格 |
| 现有资料重建 | 8/8 成功发布 V2；有效片段由 201 段变为 66 段；8 份原文和 V1 已发布版本保留 |
| 原问题 | 正确回答进入 3 分钟、持续 19 分钟、收尾 3 分钟，引用 V2 |
| 表格详细问法 | 正确给出三个阶段、时长及每阶段选曲要求 |
| 40 分钟运动 | 正确回答热身 5、主要运动 25、放缓 5、整理 5 分钟 |
| 20 分钟睡前 | 正确回答前 5、后 15 分钟，结束后停止播放 |
| MP3 转 FLAC | 正确说明无法恢复已经丢失的信息 |
| 文档外音乐节票价 | 标记证据不足，未编造票价，引用为空 |
| 本地服务 | 后端原端口 8001 健康检查成功；前端 5174 返回 HTTP 200 |

重建后 6/6 问题符合预期，其中 5 道可回答题均引用当前 V2 资料，1 道资料外问题拒答。此结果只代表这些具体案例；先前 100 题合成成绩仍为修复前的独立记录，不能代表所有真实资料的问答质量。

继续复用共享 MySQL/Redis/ES/MinIO；集成测试仅在共享 MySQL 的独立测试库中运行，测试库及临时测试账号均已清理。应用重启仅涉及后端 8001，未重启共享服务。此次无 MySQL 结构或 Redis 契约变更；用户真实资料、索引历史和验证任务保留。
