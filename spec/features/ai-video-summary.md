# AI 视频总结功能规格

## 目标

从公开视频的人工字幕、自动字幕或允许的页面文案中提取带时间戳文本，调用 OpenAI 兼容接口生成中文结构化摘要，并提供 Markdown 与 JSON 下载。

无可用字幕时执行音轨语音转写；不执行画面 OCR 或弹幕总结，不在没有可信文本来源时编造视频内容。

## 配置

文字、截图识别、语音转写各有独立的服务地址、模型和密钥，配置项如下：

| 用途 | 服务地址 | 模型 | 密钥 |
| --- | --- | --- | --- |
| 文字总结、思维导图 | `LLM_BASE_URL` | `LLM_MODEL` | `LLM_API_KEY` |
| 截图识别 | `LLM_VISION_BASE_URL` | `LLM_VISION_MODEL` | `LLM_VISION_API_KEY` |
| 语音转写 | `LLM_ASR_BASE_URL` | `LLM_ASR_MODEL` | `LLM_ASR_API_KEY` |

登录任务及无账号上下文的脚本均按进程环境变量、`.env.universal-video.local`、旧 `.env` 的顺序读取；登录任务再回退到后台保存值及默认值。修改 env 并重启后端后，新任务使用新配置；已固定配置的在途任务继续原配置。截图或语音组不要求文字密钥存在，独立连接缺少密钥时明确报错，不借用文字密钥。

后台三组配置分别展示，有环境配置的组只读并提示修改 env 后重启，API 拒绝覆盖该组；三组密钥均只返回已配置状态和掩码。保存业务开关不会将环境覆盖值或环境密钥写入数据库。无环境连接且无登录上下文时，兼容 `config/ai.json`：

```json
{
  "base_url": "https://api.openai.com/v1",
  "api_key": "replace-with-your-api-key",
  "model": "gpt-4.1-mini"
}
```

- `api_key` 和 `model` 必填，`base_url` 可选。
- DeepSeek 等兼容服务通过替换 `base_url`、`model` 和本地 `api_key` 接入，不改变接口契约。
- 旧配置文件中 `api_key` 为空时兼容 `OPENAI_API_KEY` 环境变量；旧配置路径只有在没有对应环境连接时才使用。显式配置了环境连接但密钥为空时，明确报错。
- 旧 JSON 支持独立的 `vision_base_url`、`vision_model`、`vision_api_key` 和 `asr_base_url`、`asr_model`、`asr_api_key`。旧配置完全没有某组的独立地址和密钥字段时，保留共享连接兼容；后台下次保存时将三个连接分别固定，此后彼此独立。
- 配置文件必须是合法 JSON。
- `config/ai.json` 被 Git 忽略，只提交 `config/ai.example.json`。

## 接口与任务状态

### 创建任务

`POST /api/summaries`

请求体包含公开视频 `url`、可选 `parse_record_id` 和 `generate_mind_map`（API 默认 `false`，视频页默认勾选），以及 `bilibili_subtitle_policy`（默认 `prompt`，可选 `speech`）。返回 `task_id`；联合生成时同时返回 `mind_map_task_id`。

登录用户的 B站链接在创建任务前检查字幕。需要登录时返回 `409`，`detail.code="bilibili_login_required"`；确认没有可用字幕时返回 `409 bilibili_speech_confirmation_required`，包括已登录后仍无字幕的情况。两种提示均不创建/持久化任务、下载音轨或占用 AI 线程。前端提供扫码、继续语音转写或取消；扫码成功后重新检查原视频，明确同意转写后以 `speech` 策略重新提交并跳过字幕检查。网络/访问限制返回 502，不能作为没有字幕处理。已提取字幕直接交给工作线程，避免再次请求；直接入队的自动字幕检查计入本次准备和总耗时，扫码/转写确认等待及未受理的预检不计入后续任务。

```json
{"url":"https://www.bilibili.com/video/BV1tDsgzxECr/?p=2","parse_record_id":"记录ID","generate_mind_map":true}
```

联合任务先持久化总结与关联导图任务，字幕就绪后并行生成两个结果；导图直接读取标题与完整转写文本，无需等待总结正文。两个结果各自保存状态，任一模型失败保留另一侧成功结果；字幕准备失败则两侧失败。

### 查询任务

`GET /api/summaries/{task_id}`

任务状态为 `pending`、`running`、`finished`、`failed` 或 `cancelled`。任务、字幕和结果保存到 MySQL；登录用户可恢复自己的历史任务，未知或无权访问的任务返回 404。服务中断的运行任务按现有恢复机制结束，耗时冻结在最后持久化快照，不计未知停机时间。

响应可选包含 `timing`、`model_info` 和关联 `mind_map_task_id`。旧任务没有耗时字段时显示“未记录”。同一联合任务在字幕就绪时固定文本模型配置，后台改配置后新任务使用新配置；页面显示实际模型名称和本次开始时间，便于区分旧任务残留。

进度节点：

- 8%：解析字幕或页面文案。
- 42%：文本提取完成，调用 AI。
- 无字幕转写流程：10% 准备音轨，12–26% 下载，27% 分段，28–62% 转写，64% 调用 AI。
- 82%：保存总结文件。
- 100%：总结完成。

## 文本来源顺序

1. B 站优先使用平台字幕 API，按当前操作账号读取其扫码绑定凭据；没有有效登录时由用户选择扫码或转写。字幕要求、扫码接口、账号隔离与错误规则见 `video-summary-platform-subtitles.md`。
2. 其他平台使用 yt-dlp 读取人工字幕和自动字幕。
3. 字幕按中文简体、中文、中文繁体、英文的顺序选择。
4. 字幕格式按 VTT、SRT、JSON3、JSON、SRV3、TTML/XML 顺序选择。
5. 无字幕或字幕无法解析时，总结任务下载音轨、校验时长并调用语音转写服务；抖音因 `fresh cookies` 无法获取字幕时复用浏览器解析取得音轨。
6. 语音模型使用 `LLM_ASR_MODEL`，独立使用 `LLM_ASR_BASE_URL` 和 `LLM_ASR_API_KEY`；服务需支持 `/audio/transcriptions`，最长处理 4 小时音轨。逐段显示转写进度，失败或取消时清理临时音频。
7. 来源标记为「语音转写（分段时间戳）」。只返回文本的服务以约 60 秒分段起点定位，生成摘要时明确告知模型时间戳为近似值。
8. 没有任何可用文本时任务失败，不调用总结模型。

## 字幕解析

- 支持 VTT、SRT、YouTube JSON3 和 B 站 JSON 字幕。
- 清理 HTML 标签、重复空白和连续重复片段。
- 时间戳统一格式化为 `H:MM:SS` 或 `M:SS`。
- API 响应最多返回 500 个字幕片段。
- 提交给 AI 的文本最多 28000 个字符，超出后追加截断提示。

## AI 输出契约

使用 `chat.completions` OpenAI 兼容接口，温度为 `0.2`。摘要必须包含：

- 概览
- 关键要点
- 时间线章节
- 适合保存的笔记

模型不得补充字幕或页面文案中不存在的事实。AI 返回空内容时任务失败。

总结请求显式设置 180 秒超时、关闭 SDK 隐式重试。网络错误、429、500、502、503、504 最多尝试两次，等待支持数值 `Retry-After`（1–10 秒）并检查取消状态；认证、参数、输出格式错误不盲目重试。模型和 ASR 请求共用进程内最多 3 个在途请求限制。

2026-10-21：硅基流动 `api.siliconflow.cn` / `api.siliconflow.com` 的 `deepseek-ai/DeepSeek-V4-Flash` 与 `Pro/deepseek-ai/DeepSeek-V4` 在总结、导图中统一显式发送 `enable_thinking=false`（OpenAI SDK 的 `extra_body`），同时使用 `stream=true`、`stream_options.include_usage=true` 采集首字和 token。其他服务/模型沿用原请求参数和非流式方式，避免发送不支持的扩展字段。此参数仅作用于视频总结与导图，不修改全局模型配置或语音转写。流式只用于服务端测量，前端仍通过原任务接口轮询完整结果。

流式请求必须收到 `finish_reason` 才视为传输完成；缺少结束标记则丢弃本次残缺正文，在原最多两次尝试范围内重试，不能拼接两次响应。消费流期间检查取消并关闭流；不持久化思考原文或原始响应。关闭思考通常减少额外推理等待及 token，但复杂推理与导图关联质量可能下降；网络/服务波动、输出长度和 ASR 仍影响总耗时，不承诺固定速度。参数依据[硅基流动接口说明](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions)。

## 结果文件

- Markdown 文件包含 AI 摘要以及本次 `SummaryResult` 的“字幕/转写文本”章节（与响应一致，最多 500 段）；任务持久化快照另存完整转写，供导图使用。
- JSON 文件保存结构化 `SummaryResult`，不写入下载 URL 字段。
- 文件保存到 `downloads/_summaries`，名称由任务 ID 和安全化标题组成。
- 通过 `/api/summary-files/{filename}` 下载，只允许访问安全化后的文件名。

## 前端行为

- 解析成功后允许创建总结任务，默认按钮为“生成总结与思维导图”，可取消勾选只生成总结。
- 前端轮询任务状态并显示进度、错误、来源、语言和字幕数量。
- 完成后展示纯文本摘要和最多 80 条字幕，并提供 Markdown/JSON 下载入口。
- 新解析开始时停止旧总结轮询并清理旧结果。
- B站需要登录时打开选择弹窗，支持哔哩哔哩 App 扫码、确认、刷新、失效、取消和继续语音转写。无可用字幕时主动弹出转写确认并说明耗时通常更长，确认或取消前不开始下载/转写。扫码后保留原视频、分 P、解析记录和原导图选项；仍无字幕时再确认转写。视频页显示连接状态、昵称、解除绑定入口；无字幕确认不清除绑定；切换账号/记录或卸载页面后不再自动重试旧请求。
- 总结与导图独立轮询，单个轮询禁止请求重叠；已有任务运行期间禁用重复生成。任一结果先完成即可查看。
- 现有视频页增加“执行耗时”区域：实时总耗时、阶段耗时、阶段完成状态、分段进度、请求次数、重试等待、实际模型和任务时间。展开详情可看下载、转换、转写及导图分段。
- 顶部始终独立展示“本次执行总耗时”，下方三个指标为“AI 总结耗时”“思维导图耗时”“字幕 / 转写准备耗时”。AI 总结仅取 `summary_model` 阶段，导图仅取 `map_model` 阶段；不把准备、排队和保存混入模型阶段。模型阶段本身包含接口等待与重试。展开详情按调用展示尝试次数、结果状态、思考模式、首字耗时、思考 token 和接口耗时；首字特指正文开始，思考 token 仅取服务返回的 usage，不用响应快慢推测。未提供 usage 或非流式首字用“未记录”，不能伪装成零。
- 阶段明细按“总结流程”“思维导图流程”分组，各自显示任务全程用时与状态；“展开分段详情”显示子阶段。顶部标注本次执行范围及开始/结束时间。单独生成导图时保留所选总结的耗时作为参考，标注“之前执行 / 未计入本次总耗时”。
- 阶段横条统一表示完成进度：已完成阶段均为绿色满条、勾选图标及“已完成”标记，耗时仅由右侧数字表达，不再以横条长度和偏移表示时间。执行中为蓝色，已知多段进度按完成段数计算；单次模型请求或未知进度使用不定进度动效，不推测百分比。失败为红色、取消为灰色状态标记，两者均不显示完成进度条。顶部、指标卡及流程标题复用相同状态样式，分段数、请求次数和重试等待合并为详情行。窄屏允许标签换行，尊重减少动态效果的系统偏好。
- 总结与导图各自按最近收到的快照推进计时，另一任务轮询更新不会重置本任务显示时间。阶段尚未开始、未执行、未生成或旧数据未记录分别提示，不伪装成 0 秒。
- 总耗时按任务开始到最后一个关联任务结束的时间跨度计算，不累加并行阶段或父子阶段。单独重新生成导图时仅显示本次导图耗时，排除用户两次操作间的空闲。
- 最近状态获取耗时和导图首次布局耗时单独显示，不混入后端生成总耗时；浏览器布局耗时仅代表本次打开页面。

## 执行调度、数据与兼容

- AI 编排线程池最多 4 个任务，下载使用原有 2 个工作线程；导图模型分块最多并行 2 个，ASR 分块最多并行 3 个，结果均按输入顺序归并，线程间传递账号上下文。取消后停止继续派发，等待在途分段退出后清理临时音频。
- MySQL 无新增表、列、索引或关系；`timing`、`model_info`、`mind_map_task_id` 写入已有 `video_summaries.content`，导图计时和模型写入 `video_mind_maps.content`。表结构、JSON 契约、写入与恢复规则及回滚见[性能记录](../performance/ai-video-generation-2026-10-19.md)。
- 每次模型调用完成或失败时，在现有 `content.timing.stages[].model_requests` 追加可选测量对象，字段为 `{attempt:1,status:"finished或failed",elapsed_ms:11200,first_output_ms:1100,first_content_ms:1100,reasoning_tokens:0,prompt_tokens:1802,completion_tokens:1285,thinking_enabled:false}`。`first_output_ms` 是首个正文或思考片段，`first_content_ms` 是首个正文片段；均从实际接口调用前开始计，包含网络和服务端等待，排除本地 provider slot 等待。`elapsed_ms` 到完整流读完/异常为止；未知首字和 token 为 null；`thinking_enabled` 仅表示请求参数，未明确设置为 null，不推断服务实际默认模式。并行分块按完成顺序追加、各自测量，`attempt` 是单个分块的尝试编号；不跨分块相加首字耗时。失败请求可能没有 usage；非流式仍记录接口用时及服务提供的 token。
- 本次提示选择、请求参数和测量对象不需要新表、字段、索引、外键或关系，无新增 SQL 表结构和迁移。复用 `video_summaries.content` / `video_mind_maps.content` JSON 及原账号/总结关联；计时沿用原快照保存和恢复机制。Redis 没有新增/修改 key 模板、示例、类型、值结构、TTL、读写、失效或一致性规则：确认在页面内存，模型测量在任务内存并随现有 MySQL 快照落盘，不增加缓存。回滚本次请求/测量/弹窗代码即可；JSON 可选字段保留，旧代码忽略，历史任务无该字段仍显示未记录，无数据回滚。
- 计时仍采用 MySQL 已有任务快照。B站扫码新增 `videodream:bilibili:session:{uid}`、`videodream:bilibili:qr:{uid}` 和 `videodream:bilibili:lock:{uid}` 三种 String key；前两种加密，TTL 分别最多 30 天、180 秒，锁 30 秒。完整字段结构、示例、读写、失效、CAS/锁一致性、兼容与回滚见[字幕获取规格](video-summary-platform-subtitles.md#数据与性能记录)。MySQL 无新表/列/索引/关系或凭据存储需求，既有任务结构不需迁移。
- 新字段均可选，无数据库迁移；回滚代码不删除历史任务，旧前端忽略新增字段。回滚后旧流程仍要求先完成总结再手动创建导图，建议等待运行任务结束后回滚。

实测数据和测量边界见[2026-10-19 链路优化记录](../performance/ai-video-generation-2026-10-19.md)。
