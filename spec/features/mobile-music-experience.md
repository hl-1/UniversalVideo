# 移动端音乐中心布局与交互

## 范围与入口

适用于宽度不超过 760px 的音乐中心；保持桌面侧栏和完整播放器布局。

- 顶部仅保留品牌／页面标题、返回和个人入口，搜索在推荐首页和单曲搜索页靠前展示。
- 底部四个入口：推荐、找歌、工具、我的。
- 推荐：主题音乐横向滑动、私人电台、继续聆听（或本地音乐）。移动端最多展示前三首，查看全部进入完整列表。
- 找歌：单曲搜索、批量找歌、场景歌单，用局部标签切换。
- 工具：任务与文件、视频下载、视频去水印。进入视频工具后使用原有音乐中心返回入口。
- 我的：喜欢、最近播放、本地和下载、试听列表、自建歌单、外观、账号安全、退出；管理员另有管理后台入口。
- 自建歌单在“我的”中可创建、打开；歌单原有编辑、删除与外观操作保留。

## 搜索交互

- 搜索框高 48px，文字 16px，提供清空、可点击放大镜和明确的提交按钮，键盘使用搜索键。
- 歌名／歌手显示“搜索”；识别到 HTTP(S) 链接后显示“解析链接”，复用现有链接解析。
- 空输入禁用提交。已有单曲下载进行时禁止提交，避免替换下载目标。
- 提交立即显示加载图标、文字和三行骨架；超过 3 秒提示仍在处理。30 秒超时取消请求并提供重试。
- 相同关键词和平台的在途请求不重复提交；用户修改输入或平台后可以重新搜索，并取消旧请求。旧请求的结果和错误均不得覆盖新请求。
- 移动端提交时收起输入键盘，结果紧接在工具栏下面。
- 成功显示真实结果和数量；无结果提供修改关键词或平台提示；请求失败显示原因和重试，保留输入。
- 平台状态默认折叠，仅在详情中逐项显示；部分平台异常不阻挡有效结果；所有来源均不可用且没有结果时提示服务失败。
- 手机端平台、格式、多选集中在紧凑工具栏。格式保留在当前工作区状态中。
- 默认隐藏多选框和批量下载工具栏，进入多选后显示；退出多选清空勾选，原有批量下载流程继续复用。
- 移动端歌曲行展示封面、名称、歌手／平台、播放和更多操作；尚未下载的歌曲显示下载按钮，已下载歌曲隐藏按钮并显示“已保存到本机”或“已在资料库”，喜欢收进更多菜单。详情及更多菜单保持一致，多选排除已下载曲目。保存目标、批量下载、数据契约及兼容回滚见[统一下载规格](unified-download-delivery.md)。
- 默认选择位置并保存：单首点击下载先打开系统保存对话框，批量在支持时先选一次本机文件夹，再逐首保存，网页展示进度条、保存大小、速度和可计算的剩余时间；未知大小不显示虚假百分比。取消位置选择不请求资源。此模式不进入浏览器下载记录；不支持选择器时提示使用浏览器管理下载，搜索多选仍可明确切换“浏览器下载（逐首）”。单曲失败不阻止后续，成功文件保留，只重试失败或取消曲目；浏览器接管不记为本机已保存。手机队列的状态、失败原因和手动链接可换行，不产生横向滚动。旧 ZIP 调用的失败隔离详见统一下载规格。
- 保存名称移除系统任务前缀，例如 `964ba09f4629.Here For It All.m4a` → `Here For It All.m4a`；批量文件不加顺序号，同名加 ` (2)` 等后缀并防止并发覆盖。正常数字歌名不截断；旧服务器文件名、资源 URL 和用户已保存文件不批量改名。此项复用现有 MySQL、Redis 和浏览器确认数据，无新增数据结构或迁移，回滚详见统一下载规格。
- 原生浏览器下载通过既有 HttpOnly 媒体 Cookie 校验，不能依赖页面 fetch 的 Bearer 请求头。逐首内容、临时文件及兼容旧 ZIP 的 GET/HEAD 均须支持此方式，并保留资源归属和会话撤销检查；创建、状态及完成接口仍须 Bearer。该认证匹配修正不改变 MySQL 表结构或 Redis 数据，验证及回滚见统一下载规格。
- 数组/v1 旧本机记录缺少逐首文件确认时显示“旧保存记录待核实”，恢复下载按钮和批量选择，不计为保存成功。“本地和下载”以可展开区域保留旧元数据；迁移备份及 v2 凭据、回滚规则见统一下载规格。此项只涉及浏览器存储，无 MySQL 表或 Redis key 变更。
- 主题封面加载失败显示占位图标，不展示浏览器破图。

## 播放器与可见区域

- 始终只保留一个挂载的音频元素，切换音乐视图、收起完整播放页不重建音频元素。
- 没有当前歌曲时隐藏播放器外壳，不为其预留底部空白；有歌曲的加载、播放、暂停和错误状态均显示播放器。
- 移动端播放器高 60px，位于底部导航上方，显示封面、歌曲信息、播放／暂停（加载或重试）、队列和关闭。
- 点击封面或歌曲信息打开完整播放页；上一首、下一首、模式、收藏、歌词、进度、音量与下载在完整播放页操作。
- 关闭停止播放、清除当前曲目并关闭相关面板；保留播放队列，下一次主动点歌重新显示。
- 加载与错误反馈在迷你播放器中可见，完整播放页显示完整错误；播放器只播放已验证的完整歌曲，不提供试听片段。
- 页面底部留白由当前播放器高度、导航高度、安全区相加决定；队列面板与提示同步定位。
- 通过 VisualViewport、输入焦点与窗口变化识别手机键盘：可编辑元素获得焦点且可见高度减少超过 120px 时隐藏底栏、迷你播放器及其浮层，音频继续；键盘关闭后恢复。
- 视频工具没有音乐底部导航；迷你播放器位于可见底部。播放视频时沿用原有暂停音频规则。

## 数据与兼容

### 完整歌曲播放与自动换源（2026-10-21）

- `/api/music/playback` 先准备完整音频再返回播放地址，响应补充 `full: true` 和探测到的 `duration`。失败返回 422 和具体原因，不创建试听会话。
- 同一平台依次尝试现有主解析、备用解析；即使接口返回了有效地址，只要实际文件不完整就继续尝试。排除重复音源地址。
- 当前平台失败后，搜索另外两个平台的同一首歌。规范化后的歌名、歌手必须相同，保留 Live、伴奏等版本词；候选时长须在原曲 `max(3秒, 3%)` 误差内，每个平台最多核验两个候选，避免换成现场版、翻唱或其他版本。
- 每个候选完整下载后检查响应类型、完整传输字节数、ffprobe 音轨时长，并用 ffmpeg 解码到结尾，检查实际解码时长。容器时长和解码时长均须符合原曲。原始时长未知时拒绝创建播放会话。
- 单文件上限 64 MiB，整个准备流程预算 90 秒；单次解析请求仍沿用既有连接／读取超时，预算到期后不再尝试后续来源。前端初次播放请求等待上限 150 秒，正常播放缓冲超时仍为 30 秒。首次播放需等待文件准备。
- 已验证文件写入本人 `downloads/users/{uid}/tmp/music-playback-{随机目录}/audio.media`，只作为临时播放文件，不加入下载列表或音乐索引。会话沿用 1800 秒 TTL、进程内最多 200 个会话；读取过期会话、创建新会话清理过期／淘汰文件。进程重启遗留目录在该用户下一次准备播放时清理，保留至少 TTL 加准备预算及 60 秒余量。
- 媒体请求继续检查资源归属、媒体 Cookie 和现有平台访问规则。播放已核验的本地临时文件，支持 GET、HEAD、单段 Range、If-Range，响应 `Cache-Control: private, no-store`，不再为浏览器重新请求未经校验的上游文件。
- 0、NaN、Infinity 等未就绪时长不触发不完整判断，保留歌曲预期时长。旧本地文件被检测为片段或版本不符时，停止并尝试远端完整来源一次；仍失败则报错，不重复换源。
- 移除“试听片段”提示；仅在有效时长确认后记一次播放历史，使用现有 `preview=false`。既有历史试听记录保留兼容。

### MySQL

无新增或修改的表、列、表结构、索引或关系。复用现有音乐库、搜索、解析、播放、下载及账号接口；完整播放继续复用现有 `resources` 表的 `playback` 资源记录，payload 保留 `source_url`、`media_url`，增加 `resolved_source_url` 表示实际来源歌曲页面。播放历史沿用 `music_history.preview` 字段。无 DDL、索引或关系变化，无需数据库迁移；历史数据无需转换或回滚。

### Redis

无新增或修改的 key，因此不涉及新 key 模板、示例、类型、值结构、TTL、读写、失效或一致性规则。继续使用已有服务端缓存策略。

### 回滚

回退本功能涉及的前端组件、样式及本规格导航，重新构建前端即可。完整播放策略回退需同时回退 `sources.py`、`full_playback.py`、播放器组件及逻辑，并重启后端；进程内播放会话失效后用户重新点击播放。遗留 `tmp/music-playback-*` 目录可在停服后清理。资源 payload 的附加字段可被旧版本忽略，无数据库或 Redis 回滚步骤。
