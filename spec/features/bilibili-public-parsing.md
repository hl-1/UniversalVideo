# B站公开 API 解析与下载

## 问题与目标

2026-10-20 腾讯云部署诊断发现：普通视频网页请求返回 HTTP 412，但同一容器中的 `x/web-interface/view`、WBI 签名播放接口正常，目标第 6 P 返回 15 个原始格式，视频及音频 CDN 的小范围读取均返回 HTTP 206。该诊断证明 API 路线可用，不等同于已完成云端整文件下载验收。

普通 BV/AV 公开视频优先使用公开 API。解析、视频下载、音轨导出和总结的 yt-dlp 字幕/音轨兜底统一使用共享适配器，避免解析成功后下载重新请求被拦截的视频网页。

本次实现只包含 API 路线修复，不新增代理、IP 伪装、Cookie 配置或部署服务。

## 解析流程

1. 使用 `x/web-interface/view` 获取元数据；BV 使用 `bvid`，AV 使用 `aid`，校验返回身份。
2. URL 没有 `p` 时选择第 1 P；有 `p` 时按响应中的 `page` 精确匹配，保留分集标题、cid 和时长。非法或不存在的分 P 直接失败，不降级到其他分集。
3. 复用当前固定版本 `yt-dlp==2026.7.4` 的 WBI 签名、`x/player/wbi/playurl` 请求和格式解析能力，匿名请求使用原有 `try_look=1` 参数。充电专属资源明确拒绝，避免把试看当完整资源。
4. 返回现有 ParseResponse 契约；每个视频格式继续附带 `+bestaudio/best` 以合并音轨。前端沿用最多 12 个格式的现有展示规则，原始格式数量可大于展示数量。
5. 网页 URL 规范为 BV 地址，移除跟踪参数，保留指定分 P。元数据和公开播放接口不需要先读取 `www.bilibili.com/video/`。
6. 字幕仅在调用方需要字幕时提取，平台字幕 API 优先级及语音转写规则保持现有规格。

解析入口纳入统一性能调度：账号内缓存和相同链接并发请求复用提取结果，提取等待最多 25 秒；前台响应不等待封面下载。B站适配器继续负责 API/网页备用及精确分 P，主流程不重复嗅探。阶段耗时通过安全日志与 `Server-Timing` 响应头提供，规范和数据兼容见[通用视频在线预览](douyin-online-preview.md)。

## 下载与兼容

- 共享 YoutubeDL 适配器在原 `BiliBili` extractor key 上替换提取器，因此解析、视频重新提取、音轨下载和短链指向的 BV/AV 视频使用相同路线；其他站点使用原有提取器。
- 下载时根据原视频 URL 和格式标识重新调用 API，使用最新播放地址。临时签名直链不成为新的持久化字段。
- 国内下载通过共享适配器选择 DASH 视频和音频，普通 HTTP 流接入统一分段/续传引擎，再由 ffmpeg 本地合并；同任务媒体连接最多 4。API 提供同一流官方 CDN 备用地址时优先标准 HTTPS 官方 CDN，保留格式标识。音轨导出沿用完整性、时长及格式校验。路由、阈值、续传边界及实测速率见[国内平台下载与速度优化](domestic-video-downloads.md)。
- API 网络错误、未知业务错误、响应结构不兼容或没有可用格式时，回退原 B 站网页提取器；双路失败保留 API 与网页两个失败原因。
- 视频不存在、明确登录/权限错误、返回身份不一致、分 P 非法或不存在时直接报错。普通 BV/AV 视频不再进入通用静态/浏览器嗅探，防止错误分集被当作成功结果。
- 活动页、番剧等非普通 BV/AV 路径，以及交互视频、需要跳转的元数据、多段 FLV，继续走原有网页提取能力，云端网页风控仍可能影响这些资源。
- 公共 API 同样可能返回风控或权限错误，本次不承诺任意 B 站资源都能解析。

## 数据明细

### MySQL

无新增或修改的表、列、索引、外键或关系。标题、时长、规范 URL、格式标识、历史和任务仍使用原有视频业务表及 JSON 契约。无需数据库迁移和数据回填；旧记录在重新解析时取得最新结果。

### Redis

无新增或修改的 key 模板、类型、值结构、TTL、读写、失效及一致性规则。沿用账号隔离的解析缓存和最长 600 秒 TTL；API 格式使用稳定格式标识，实际下载重新提取签名直链，不跨任务复用旧直链。失败结果不作为成功格式缓存。
