# 歌单链接导入与批量找歌

- 日期：2026-10-23。
- 状态：已实现；平台、测试及运行验证范围见末节。
- 入口：音乐中心 → 批量找歌 → 歌单链接；原截图和文本导入保持可用。

## 用户流程

粘贴单份平台分享文字或链接 → 选择搜索平台（默认全部）→ 一键导入并搜索 → 查看来源与进度 → 试听/确认候选 → 保存到本站歌单或批量下载。读取名单不自动下载、不写入收藏。保存歌单独立于下载，不受“跳过已下载”过滤影响。

歌单链接每次最多 500 首；平台声明总数超过 500 时，先要求选择起始位置和数量，禁止静默截断。用户也可以主动选择范围。截图和文本仍为 100 首。结果每页 50 行，全选作用于整份结果，不限当前页。

展示歌单来源、歌单名称、平台总数、实际读取数和完整性；未知总数不可显示“完整”。选取部分范围、平台截断或后续页失败均明确显示未完整导入。来源歌曲重复时按平台 ID 合并，保留首次出现位置；不同 ID 的同名歌曲保留。

## 平台支持边界

| 平台 | 支持格式与读取路径 | 边界 |
| --- | --- | --- |
| 网易云 | `music.163.com/playlist?id=...`、`#/playlist?id=...`、移动版 playlist 链接；v6 歌单详情与歌曲 ID 分批补全 | 私密、需登录、删除或接口未公开的曲目无法保证读取 |
| QQ | `y.qq.com/n/ryqq/playlist/数字ID`、含 id/disstid 的 taoge/playlist/diss 分享页；公开歌单详情 | 以平台 songnum 校验返回数量，接口截断时不宣称完整 |
| 酷狗 | `/yy/special/single/数字ID.html`、`/plist/list/数字ID`、含 specialid 的歌单页；公开 special/song 分页 | 暂不支持仅含 gcid 的新式链接、酷狗口令；名称接口无名称时显示“酷狗歌单 ID” |

短链只处理 HTTP 重定向或页面中可识别的链接元数据，不执行页面 JavaScript。无法提取 ID 时说明原因并提示使用完整链接、截图或文本。首版不接收平台账号密码或 Cookie。

酷狗公开旧接口使用 HTTP，不传用户登录凭据，不关闭 TLS 校验。平台适配不保证外部接口长期稳定，真实验收不能由桩测试替代。

## 安全、限额与任务

- 只接受三个平台白名单域名，校验公网地址、协议、端口和凭据；每个短链跳转重新校验，禁止访问本机和内网。
- 最多 6 次重定向，响应最大 8 MiB，连接/读取超时 5/15 秒。网络异常、429 和服务端错误最多尝试 3 次，退避等待可取消。
- 复用现有每用户一个活动导入、全局最多 10 个活动任务、两个工作线程限制。
- 读取分页或详情补全每批最多 100 首；搜索顺序执行，沿用每首间隔 0.4 秒及现有搜索缓存。500 首属于一个有界任务，不启动额外 worker 或中间件。
- 状态使用 `reading / recognizing / draft / searching / finished / failed / cancelled`；`partial` 表示部分搜索失败或歌单不完整，不引入与旧结果处理冲突的新终态。
- 读取进度与搜索计数分开。读取阶段分批持久化；搜索每首完成后持久化。取消保留已有结果，旧工作线程不得覆盖重试任务。
- 后续读取失败保留已读取曲目并继续搜索；用户可重新导入剩余范围。服务重启后活动任务标为失败并保存，支持重试未完成行；首版不自动续跑，不承诺跨实例任务调度。
- 浏览器保留任务 ID、编辑草稿与候选选择；删除/新增行后需重新匹配同步名单，避免只重试时恢复已删除行。

## 匹配与交付

每行保留原平台、歌曲 ID、原顺序、原始曲目信息、专辑和时长。来源信息由服务端保存；重新匹配按当前任务 row_id 关联，忽略客户端伪造的来源元数据。

搜索范围包含原平台且用户未修改原歌名/歌手时，原歌曲 ID 可作为可靠身份候选；同时检索其他候选。跨平台匹配综合歌名、歌手、版本、时长和已知专辑；专辑冲突或时长相差超过 5 秒时不自动选中跨平台候选。信息不足或版本歧义进入待确认，不等于播放失败。匹配只确认身份，播放/下载权限和完整音频仍走原校验链路。

“重试失败及未完成项”仅处理 `error / not_found / draft`，保留已完成行及选择。用户修改过名单时先重新匹配。平台不可用与没有结果分别显示。

保存结果可选现有本站歌单或新建歌单，按原顺序逐首添加。现有成员唯一键避免重复添加；部分保存失败显示已保存数量，重试继续使用目标歌单。通过 `bulk_import=true` 禁止批量添加逐首产生推荐系统强偏好事件。下载复用现有设备批量下载，未改动下载存储及目录选择。

## API

新增 `POST /api/music/imports/playlist`：

```json
{
  "share_text": "https://music.163.com/playlist?id=3778678",
  "source": "all",
  "auto_search": true,
  "start": 1,
  "limit": 500,
  "explicit_range": false
}
```

立即返回任务快照（import_id）。范围超限时返回 draft 任务、range_required=true 和歌单总数，页面要求用户选择范围重新导入。

复用 `GET /api/music/imports/{id}`、`POST /api/music/imports/{id}/cancel`。

扩展 `POST /api/music/imports/{id}/search`：完整重搜传 songs（包含可选 row_id）与 source；失败重试传 `{"retry_failed":true,"source":"all"}`，不得同时传新名单。歌单任务最多 500 行，旧导入仍限制 100 行。

扩展现有 `POST /api/library/playlists/{id}/tracks?bulk_import=true`，默认 false 保留单首添加的推荐行为。新入口豁免“把 playlist 当任务 ID”的路径解析，但不豁免登录及用户权限检查。任务查询、搜索、取消和保存均验证资源归属。

## MySQL 数据明细与兼容

无新增表、无结构或索引修改、无 Flyway 新迁移。导入任务继续存储于 `resources` 的 `kind=music_import`。当前完整表结构：

```sql
CREATE TABLE resources (
    kind VARCHAR(24) NOT NULL,
    resource_key VARCHAR(255) NOT NULL,
    user_id BIGINT NOT NULL,
    payload MEDIUMTEXT NOT NULL,
    created_at DOUBLE NOT NULL,
    updated_at DOUBLE NOT NULL,
    deleted BOOLEAN NOT NULL DEFAULT FALSE,
    device_id CHAR(36) NULL,
    PRIMARY KEY(kind, resource_key),
    INDEX resource_owner(user_id, kind),
    KEY resource_device(user_id, kind, device_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`resource_key` 为任务 ID；`user_id` 逻辑关联 users.id，无数据库外键。现有账号服务以 user_id 控制资源权限。payload 使用 JSON 文本，原字段继续有效；新增可选字段如下：

| 字段 | 内容 |
| --- | --- |
| schema_version / input_kind | `2` / `playlist` |
| source | 搜索平台：all、qq、netease、kugou |
| playlist | provider、playlist_id、规范化 url、name、total（可空）、read_count、complete、start、limit、range_complete |
| range_required | 是否需要用户明确指定范围 |
| searched / search_total | 本轮搜索进度，包括只重试子集 |
| partial | 歌单或搜索结果是否部分完成 |
| rows[].origin | position、album、track（无 token 的来源 Track、专辑和位置） |

不持久化原分享文字、Cookie、平台密码或临时音频地址。用户明确保存歌单时，通过原接口写入 music_playlists、music_tracks、music_playlist_tracks；表结构、索引和关联不变，成员去重沿用原机制。本次仅为批量保存抑制逐首推荐事件，不改变已有推荐数据。

旧任务没有新字段时使用原流程。回滚前停止新入口和活动任务，备份本次 music_import 任务快照；将 reading 状态转换为旧版能识别的 failed，并说明中断原因，再回滚应用。保留 task payload 和用户已保存歌单；不删除历史资源，不执行全库或缓存清空。旧版本不能使用新增歌单入口及 500 首重搜，不承诺降级后继续处理新格式的大任务。

## 搜索并发、耗时及设备下载状态（2026-10-24）

### 实现行为

- 单个导入任务使用滑动窗口，同时最多处理 10 首歌曲；取消原来每首固定等待 0.4 秒。结果按原始行写回，乱序完成不改变歌曲顺序。失败不阻塞其余歌曲；取消后停止补充任务并丢弃旧轮次的晚到结果，已开始的网络请求由原请求超时收尾。
- QQ、网易云、酷狗各自独立线程池，每个平台每进程最多 2 个请求，发起间隔至少 150ms。两个导入调度任务共享 20 个歌曲工作线程和平台配额。8001/8002 为独立进程，这不是跨进程或分布式总限流。
- 同轮次相同平台、查询和页码合并进行中的请求，不跨取消令牌关联。非空结果缓存 120 秒，上限 1500 条；空结果不缓存。HTTP 429 或连续三次异常触发 30 秒退避；已返回有效候选后连续五次空结果触发退避并提示平台不可用。空结果阈值属于保守保护，不能据此断定平台限流，可能影响确实无结果的连续查询。
- 校验网易云 code、QQ code、酷狗 status/error_code，业务错误不再伪装为正常空列表。平台失败显示可重试；不保证外部平台可用或所有歌曲都有候选。
- 任务记录累计总耗时、排队、读取、识别和搜索阶段秒数，以及本轮搜索秒数。总耗时仅累加任务活动阶段，不计用户编辑等待。页面按最近服务端快照补计活动时间；完成、失败、取消后冻结，重试保留累计值。搜索完成至少 10 首后按本轮平均吞吐估算剩余时间，平台退避会影响估算准确性。
- 老任务未记录耗时则显示“耗时未记录”。服务重启恢复中的任务保留最后持久化时长，标记 interrupted，不将停机时长算入搜索；快照最多每 0.5 秒持久化一次，终态立即保存。
- 歌名、歌手及候选选择控件底色透明，悬停和聚焦不恢复深色背景；人物背景保留。下拉选项弹出层保留可读底色。顶部搜索框取消输入框内部的重复彩色焦点框，外围保留焦点指示。耗时文案可换行，移动端表格继续局部横向滚动。
- “已下载”、试听本地优先和跳过下载统一读取当前账号、当前设备可读曲库，严格使用 provider + identifier 身份。移除同名歌手及相近时长关联；服务器缓存文件和下载回执本身不构成设备已下载。进入页面、返回页面、恢复窗口焦点、任务结束、试听及下载前刷新文件可读性；失效文件不再跳过下载。

### 数据兼容与回滚

MySQL 不新增或修改表、列、索引及关系：已有 `resources` 的 `kind=music_import` JSON payload 增加可选 `timing` 对象。字段为 `total_seconds`、`queue_seconds`、`read_seconds`、`recognize_seconds`、`search_seconds`、`round_seconds`、`round_started_at`、`round_search_base`、`phase`、`active_since` 和恢复时的 `interrupted`。秒数为非负浮点数，时间戳为 Unix 秒，phase 为空表示停止计时。原所有权、资源键和删除规则不变。旧 payload 无 timing 仍可读，回滚旧代码会忽略这些可选字段，无需 DDL、Flyway 新版本或删除业务数据。已有 V3 性能日志表不变。

Redis 不新增或修改 key：并发令牌、请求合并、退避和 120 秒缓存均为进程内状态；进程退出即失效，没有 Redis TTL 或一致性规则变更。多进程总配额若需统一，应另行设计共享协调方案。
