封面、通用字幕文件和关联音频封面现已接入来源平台网络路由；国内专用字幕 API 仍按其原有独立 requests 路径请求。辅助资源的路由统一不等于采用大文件分段加速。

## 下载规则

1. 使用实际 `GET Range: bytes=0-0` 探测。正确的 206、Content-Range、单字节响应、总长度、可用文件标识同时满足才分段，不只相信 HEAD/Accept-Ranges。
2. HTTP 文件大于 16 MiB（16,777,216 字节）最多 4 个连接；小文件 1 个连接。无正确 Range 或稳定标识时回退单连接完整 GET。
3. 标识优先强 ETag；Last-Modified 必须比服务器 Date 早至少 60 秒，同时验证总长度。弱 ETag 不作为续传依据。
4. 每段使用 If-Range，核对响应范围、总长度、标识和实际字节数。拒绝超长/短段；源站忽略 Range 或范围错误时清理分段并回退单连接。
5. 请求 `Accept-Encoding: identity`，避免压缩字节偏移失配。网页、JSON、图片、空文件不能成为成功媒体。
6. 网络请求初次失败后最多重试 3 次。分段从已写入且重新验证的偏移续传；无稳定标识的完整 GET 重试从头开始。
7. 全部分段完整后本地组装并原子替换目标，失败或取消不发布不完整文件。
8. 401/403/410 或内容标识变化时最多重新解析一次，新地址仍需验证标识才能复用分段。嗅探格式匹配原标签/容器/分辨率，匹配不到要求重新选择，不静默换清晰度。

B站普通 DASH 使用共享公开 API 适配器取得所选视频和音频，依次下载，每条流最多 4 连接，再本地无重编码合并；两条流不同时各开 4 连接。音轨任务仅下载音频源，或从混合源中提取，并保留完整性及预期时长校验。

HLS/DASH 使用原生下载器，最多 4 个分片，失败最多重试 3 次，缺失分片报错，不回退远程 ffmpeg。直播、DRM、不支持的清单明确失败。清单分片使用任务临时目录，失败后清理；跨任务续传当前仅适用于有稳定标识的普通 HTTP 文件。

执行池仍最多 2 个下载任务，国内正文连接最多约 8 条。解析/探测不与同任务四条正文连接叠加。后续连续多个视频下载可复用该队列和单任务引擎；本次未增加视频批次 UI/API/批次表。

## 进度与浏览器保存

沿用 `TaskResponse.message` 显示当前视频/音频阶段、实际下载量/总大小、速度及 ETA；未知长度不伪造总大小/ETA。HTTP 速度为本次新增有效字节除以耗时，历史分段不计为新速度。分离流的百分比按已完成流与当前流组合。合并单独显示“本地合并”。

工作线程汇总字节并限制进度频率，持久化沿用约每秒一次。

### 浏览器保存状态与并发修复（2026-10-20）

后端任务完成代表应用中的视频文件已就绪，浏览器另存到用户目录属于后续独立操作。实际问题样本为 750,503,209 字节 MP4，ffprobe 检查 H.264 + AAC、时长 1572.524989 秒正常，不能把浏览器“保存中”当作后端仍在下载。

原页面允许运行中再次创建下载，新的 interval 覆盖旧定时器引用；旧轮询继续请求，已经发出的回调也可能同时进入完成分支。保存句柄在成功之后才清空，又缺少保存互斥，可能重复 createWritable 并产生多个浏览器临时文件。原实现对每个网络小块调用文件写入，大文件调用次数过多；没有保存进度、取消或无进展超时。这些问题由前端保存生命周期修复，不修改后端成品文件。

- 同一工作区已有 pending/running 下载或正在保存时，禁止再次提交下载。后端原有任务队列仍保留；连续多个视频的批次功能后续单独实现。
- 轮询改成一次响应处理完成后再等待 1200 ms，不重叠请求。开始、恢复和切换任务统一管理定时器与版本，忽略过时响应；终态只处理一次，自动保存前先领取并清空句柄。刷新历史记录不阻塞自动保存。
- 自动和手动保存共用一个活动保存，固定任务 ID、下载 URL 和记录版本，禁止重复创建 writer。切换解析记录、删除当前记录、重新解析或组件卸载时取消旧保存；旧结果不能覆盖新任务状态。
- 支持文件选择器时流式读取 response.body，以最多 1 MiB 缓冲合并写入，不缓存整个大文件。显示已写入量、有效 Content-Length 对应总量/百分比，以及“正在完成文件写入”。未知长度只显示已写量。文件长度不符或空响应不提交成功。
- 读取、写入、结束写入等单个操作超过 60 秒没有进展时中止并提示重试；正常持续传输不受 60 秒总时长限制。可取消保存，失败/取消清理 reader/writer 并恢复按钮，重试直接读取原成品，无需重新下载源站。浏览器选择位置对话框遵循浏览器自身取消操作。
- 仅 writable.close 成功才标记“已保存到本机”，主按钮显示“已保存”，保留“再次另存为”。完成标记在此浏览器 localStorage 中按随机任务 ID 保存：key `videodream.video.saved.<task_id>`，示例 `videodream.video.saved.acca8df7b30d`，值 `'1'`。不保存本机路径、句柄、凭据或媒体内容；记录切换与刷新可恢复，清理站点存储后失效，表示曾成功保存，不检测之后手工移动/删除的文件。存储不可用时仍可保存并在当前页面显示成功。
- 不支持文件选择器的浏览器沿用 Blob 下载，只显示“已交给浏览器下载”，不伪报本机写入成功。新版本无法追溯旧版本未记录的本机保存结果。

此次修复不新增或修改 MySQL 表及 Redis key；完成标记属于浏览器本机状态，不作为后端任务状态或跨设备同步数据。回滚前端代码即可，遗留完成标记不影响旧版本。

## 本地续传状态

目录 `downloads/users/{user_id}/tmp/transfers/<sha256(owner:source-quality-key)>/`。key 包括用户、原页面、媒体类型、音频格式、所选格式和流序号；目录仅保存摘要。账号隔离，同 key 使用本进程互斥锁。成品写入该用户 `files/`；下载与合并的中间文件使用该用户 `tmp/`，沿用统一存储路径校验。旧 `downloads/.transfers/` 中的失败分段只按原期限清理，不作为新下载的写入目录；升级后可重新下载，成品迁移按账号规格执行。

`state.json` 示例：

```json
{
  "version": 1,
  "total": 20000000,
  "identity": ["ETag", "\"sample-version\""],
  "ranges": [[0,4999999],[5000000,9999999],[10000000,14999999],[15000000,19999999]],
  "owner": 7,
  "task_id": "sample-task",
  "updated": 1792500000
}
```

分段为 `0.part` 至 `3.part`，实际长度代表完成偏移。元数据不保存明文页面/签名 URL、Cookie、Authorization；错误响应隐藏媒体 URL。

失败分段有效期 24 小时。服务启动、历史任务心跳（约 10 秒）、新下载触发清理，持锁的活动目录跳过。成功立即清理；取消、任务/解析记录删除、账号删除/停用按 owner/task 清理，活动任务结束时清理。当前实现面向单进程服务，不作为多进程共享目录锁方案。

## MySQL 与 Redis

MySQL 无新增/修改表、字段、索引、外键或关系。继续使用原下载任务、解析记录及文件资源契约；速度信息进入原 message，本地分段不写数据库。无需迁移、回填或结构回滚。

Redis 无新增/修改 key 模板、类型、值结构或 TTL。媒体过期时先删除原账号既有解析 key 再解析。既有模板 `<redis_prefix>video:parse:<uid>:<sha256(url)>`，示例 `videodream:video:parse:7:<64位摘要>`（前缀以配置为准），String，ParseResponse JSON，TTL 按原规则最长 600 秒。重新下载继续验证媒体身份，缓存更新不能导致混合两版文件。24 小时有效期属于本地文件，不是 Redis TTL。

## 预计速度与真实测试

大文件、源站和磁盘不限速时，目标接近同网络常用下载软件。下表为条件目标，MB/s 使用十进制，不是平台保证值：

| 接入带宽 | 理论上限 MB/s | 工程目标 MB/s |
| --- | ---: | ---: |
| 100 Mbps | 12.5 | 8–11 |
| 300 Mbps | 37.5 | 25–33 |
| 1000 Mbps | 125 | 70–110 |

源站只限制单连接时，四连接可能提升约 2–3.5 倍。源站限制单 IP 总速率或单连接已跑满时不保证提速，小文件可能因连接/探测稍慢。解析、传输、合并、浏览器保存分别耗时，不能把总任务耗时当纯下载速度。

2026-10-20 本机实测（下表 MiB/s，1 MiB = 1,048,576 字节）：

| 场景 | 文件字节 | 单连接 | 四连接 | 校验 |
| --- | ---: | ---: | ---: | --- |
| 本地受控 HTTP，每连接独立延迟 | 8,388,608 | 1.734 s / 4.614 MiB/s | 0.500 s / 16.000 MiB/s | SHA-256 相同，峰值确为 1/4 连接 |
| B站 `BV1qW4y1a7fU?p=11`，1080p，官方 CDN | 18,588,371 | 1.859 s / 9.536 MiB/s | 2.094 s / 8.466 MiB/s | SHA-256 相同，峰值确为 1/4 连接 |

受控测试临时降低分段阈值，仅用于验证并发机制；生产阈值仍 16 MiB。B站样本单连接已接近当前链路能力，四连接没有提升；不能据此宣称国内平台普遍提速倍数或实测运营商带宽。此前约 0.4 MB/s 失败记录来自国外源，不作为国内优化基线。

完整任务：`BV1qW4y1a7fU?p=6`，选择 `30011+bestaudio/best`，新入口 3.656 秒完成解析、下载、本地合并，22,167,427 字节。ffprobe 确认 HEVC + AAC，时长 726.435624 秒。独立 M4A 1.953 秒完成，12,764,790 字节，仅 AAC，时长相同。临时媒体已清理；该总时长不代表纯传输速度对比。

小红书、抖音、微博的分类/直连与通用引擎有自动测试覆盖，本次无可复现公开样本完成三平台真实整文件测速，不宣称三平台实测速率。风控、签名、登录和 CDN 总限速仍影响结果。
