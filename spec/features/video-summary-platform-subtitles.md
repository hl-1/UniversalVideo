# 视频总结字幕获取规格

## 目标

视频总结优先使用平台提供的结构化字幕轨；没有可用字幕时提取音轨并语音转写。不使用弹幕或画面 OCR。

## 获取顺序

1. B 站链接先调用 `x/web-interface/view` 获取分 P 的 `cid`。
2. 调用 `x/player/wbi/v2` 获取创作者上传或平台生成的字幕列表，并校验业务状态以及返回的 `bvid`、`cid` 与目标视频一致。
3. 按现有语言优先级选择字幕，下载 B 站 JSON 字幕并映射为带时间戳文本。
4. 登录用户创建 B站总结时，在任务入队前完成字幕检查。匿名接口要求登录时，使用当前操作账号绑定的 B站凭据重试；没有有效凭据则返回 `409 bilibili_login_required`，由用户选择扫码或语音转写。
5. 扫码确认后自动重试原视频，保留分 P、解析记录及导图选项；确认没有可用字幕时，无论是否已绑定账号，返回 `409 bilibili_speech_confirmation_required`，弹出“本视频暂无可用字幕，需要提取音轨并进行语音转写，耗时通常更长”，由用户选择“继续语音转写”或“取消”。登录仅用于访问受限字幕，不能保证视频有字幕；扫码后仍无字幕也必须经过该确认。网络、访问限制、业务错误和无效字幕返回明确错误，不静默当作无字幕。
6. 用户明确选择语音转写时以 `bilibili_subtitle_policy="speech"` 重试，跳过 B站字幕检查。字幕检查结果在内存中直接交给生成线程，避免重复请求；扫码与转写确认期间均不创建总结/导图任务、不下载音轨、不写失败历史、不占用 AI 工作线程，人工等待不计入生成耗时。取消或切换账号/视频后丢弃迟到结果，不自动创建任务。
7. 无账号上下文的旧脚本保留平台 API 与 yt-dlp 的兜底顺序。不把 `danmaku` 当作字幕。

B 站普通 BV/AV 视频通过共享公开 API 适配器获取元数据和播放地址，旧脚本的 yt-dlp 字幕回退和后续音轨下载不再以读取视频网页为前提，详见 [B站公开解析](bilibili-public-parsing.md)。

## 兼容与错误

- 保持现有 `SubtitleSegment`、总结任务和前端响应契约不变。
- 支持 URL 的 `p` 参数，选择对应分 P 的 `cid`。
- 登录用户的 B站 API 网络错误、非零业务码和异常响应明确返回 502；旧脚本兼容回退 yt-dlp。
- 2026-10-19 真实验证发现旧 `x/player/v2` 在相同视频 ID 下返回内容变化的字幕，已迁移播放器接口；错源验证轮次不纳入性能样本。身份校验无法证明字幕语义，平台返回仍需结合实际内容核验。
- 登录用户仅使用自己的 B站绑定凭据；管理员查看他人记录时仍使用管理员本人的 B站会话，不根据数据归属选择凭据。服务不读取本机浏览器 Cookie；无账号上下文的旧脚本保留浏览器兼容逻辑。
- 匿名接口返回 `need_login_subtitle` 时提示扫码；绑定凭据失效时提示重新登录。已登录但仍无字幕时用 `nav` 独立验证登录，区分会话失效与确实没有字幕。验证网络错误保留原绑定并提示重试。
- 仅接受 `.bilibili.com` 根域、根路径且未过期的扫码 Cookie，必须有 `SESSDATA`；先用 `x/web-interface/nav` 验证登录再保存。字幕 CDN 请求不携带 Cookie，不返回或记录原始 Cookie、SESSDATA、上游二维码凭证。
- 字幕地址以 `//` 开头时规范化为 `https://`。
- `ai-*` 语言代码按对应基础语言参与优先级排序；`type=1`、`ai-*` 或非零 `ai_type` 的字幕统一标记为自动字幕。
- 两种方式均未命中时进入语音转写。未配置 `LLM_ASR_MODEL` 时明确提示配置语音转写模型。
- 音轨经过时长校验，转成 16 kHz 单声道 WAV，按约 60 秒分段调用同一 AI 服务的 `/audio/transcriptions`。
- 只返回文本的语音服务使用音频分段起点作为时间戳；返回合法细粒度时间戳时转换为视频绝对时间。结果来源标记为「语音转写（分段时间戳）」。
- 请求遇到网络错误、429 或暂时性服务错误最多尝试三次；转写失败时不提交不完整文本给总结模型。临时音频在成功、失败或取消时清理。
- ASR 分段最多并行 3 个，结果按音频原顺序拼接，进度按完成段数上报。进程内与文本模型共享最多 3 个在途请求限制，并在线程间传递账号上下文。
- 429/暂时性错误支持数值 `Retry-After`，等待上限 10 秒；网络错误指数等待。请求连接/读取超时为 10/120 秒，等待与分段派发检查任务取消。首个分段失败后停止新派发，等待在途任务退出后清理音频，避免 Windows 文件占用问题。
- 记录音轨下载、音频转换、音频分段、ASR 总阶段和各分段耗时、请求次数、重试等待。转写阶段与下载/分段均属于“字幕与转写准备”的子阶段，统计总耗时不能重复相加。

## B站扫码接口与交互

接口均要求 VideoDream 登录，账号 ID 从当前认证上下文获取，禁止客户端指定账号。

| 接口 | 行为与响应 |
| --- | --- |
| `GET /api/videos/bilibili/session` | 返回 `bound`、`nickname`、`expires_at`；每五分钟按需验证绑定，实际使用字幕遇到登录限制时再次验证 |
| `DELETE /api/videos/bilibili/session` | 清除当前用户的绑定、二维码与锁；账号停用/删除时复用该清理逻辑 |
| `POST /api/videos/bilibili/qr` | 生成新二维码，返回不透明 `login_id`、本地生成 PNG 的 `qr_image` data URL、`expires_at`、`status`、`poll_after=3` |
| `GET /api/videos/bilibili/qr/{login_id}` | 返回 `waiting_scan` / `waiting_confirm` / `confirmed` / `expired`；确认时仅返回绑定状态与昵称 |
| `DELETE /api/videos/bilibili/qr/{login_id}` | 只取消当前用户匹配的二维码，旧 ID 不能取消刷新后的二维码 |

使用 B站 Web 扫码生成/轮询接口及浏览器请求头；二维码由服务器本地编码，不使用第三方二维码服务。哔哩哔哩 App 扫码后须在 App 内确认。二维码最多有效 180 秒，前端和后端均以三秒间隔限制轮询；过期可刷新，访问限制或网络失败显示错误和重试入口。等待、刷新和错误状态都可取消或继续语音转写。切换账号、视频记录或卸载页面时结束等待并丢弃迟到结果。

生成前字幕检查复用 `POST /api/summaries` 的入队前检查，不增加独立预检请求或缓存。可用字幕直接入队；需要登录弹出扫码选择；确实没有字幕弹出转写确认；检查失败显示错误，可重新点击生成重试。转写确认复用同一弹窗的提示模式，不展示或生成二维码，不清除现有绑定。确认后沿用最初的视频链接、分 P、解析记录及导图选项。

视频页面显示 B站绑定状态、昵称和解除绑定入口。扫码弹窗支持关闭、Escape 和键盘焦点循环；绑定只用于字幕访问，不改变视频文件下载授权。

## 数据与性能记录

- MySQL 无新增或修改表、列、索引和关系；阶段计时写入原有 `video_summaries.content.timing`，契约与恢复规则见[链路性能记录](../performance/ai-video-generation-2026-10-19.md)。
- MySQL 不保存 B站凭据，无新增/修改表，因而无新表结构、列、索引、外键、关系或 SQL 迁移；现有任务表及关系保持原契约。扫码等待没有任务记录，最终生成结果沿用原表。
- Redis 新增三个命名空间，均为 String，按 VideoDream 用户隔离；已有解析缓存和账号登录会话 key 不变。音频临时文件不写入 Redis。

| key 模板（示例） | 完整值结构（加密前） | TTL |
| --- | --- | --- |
| `videodream:bilibili:session:{uid}`（`videodream:bilibili:session:42`） | `{version:1, uid:42, bilibili_uid:"7", nickname:"昵称", cookies:[{name:"SESSDATA",value:"凭据",domain:".bilibili.com",path:"/",expires:Unix秒或null}], created_at:Unix秒, expires_at:Unix秒, last_verified_at:Unix秒}` | Cookie 实际最早过期时间与 30 天取较小值；校验只保留剩余 TTL，不续期 |
| `videodream:bilibili:qr:{uid}`（`videodream:bilibili:qr:42`） | `{version:1, uid:42, login_id:"随机不透明ID", provider_key:"上游扫码凭证", status:"waiting_scan或waiting_confirm", created_at:Unix秒, expires_at:Unix秒, last_poll_at:Unix秒}` | 最多 180 秒；上游更早失效立即删除，轮询写入仅保留剩余 TTL |
| `videodream:bilibili:lock:{uid}`（`videodream:bilibili:lock:42`） | 唯一操作 nonce 字符串 | 30 秒；`SET NX EX` 获取，比较 nonce 后释放 |

会话和二维码 JSON 使用 Fernet 加密，密钥从现有稳定服务端 `VIDEODREAM_JWT_SECRET` 经 HKDF-SHA256 派生，独立上下文 `videodream/bilibili/credentials/v1`。Redis 中只存密文，前端只获得二维码图片、业务 ID 和公开状态；不存在全局共享 B站 Cookie。密钥轮换、Redis 丢失、过期或不可解密时要求重新扫码。

读写与一致性：生成/轮询使用用户级锁；Lua 同时比较锁 nonce 和原二维码密文，匹配后才更新状态。扫码成功在同一个 Lua 操作内保存会话并删除二维码；解绑原子删除三种 key，迟到的生成/轮询因锁或二维码不匹配而失效，不能恢复会话。取消只比较并删除匹配二维码；刷新替换 ID，旧 ID 立即失效。验证会话使用原密文 CAS 更新/删除，迟到的验证不得覆盖或删除新会话。Redis 失败返回服务错误，不借用其他用户或本机浏览器凭据。

迁移与回滚：无需数据库迁移，滚动发布时新增 key 由新代码按需创建；旧客户端默认收到登录提示 409，可升级客户端或明确提交 `bilibili_subtitle_policy="speech"`。回滚前等待运行任务退出，回滚功能代码及新增依赖即可；新 Redis key 自然过期，也可仅清理 `videodream:bilibili:*`，禁止清空其他认证/业务缓存。回滚不修改历史字幕或转写；重新上线后凭据缺失则重新扫码。

2026-10-21 转写确认调整不新增或修改 MySQL 表、列、索引、外键或关系：用户选择仅存在当前页面内存，确认后沿用既有任务表，无新表结构或 SQL 迁移。也不新增或修改 Redis key 模板、示例、类型、值结构、TTL、读写、失效和一致性规则，沿用上表三种登录 key。旧客户端遇到新的 409 会显示错误，需同步升级前端；回滚本次前后端确认分支即可恢复自动转写，既有数据无需处理。

旧任务允许没有计时字段。转写并发不改变字幕优先、分段时间戳与结果完整性要求。[2026-10-19 实测](../performance/ai-video-generation-2026-10-19.md)分别记录平台字幕链路和强制 ASR 分支，避免将未实际发生的下载/转写阶段记为零。
