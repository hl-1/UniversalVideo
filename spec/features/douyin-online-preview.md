# 通用视频在线预览功能规格

国内平台预览准备和旧版抖音流代理遵循[国内平台下载与速度优化](domestic-video-downloads.md)的显式直连策略；保留本文的资源限额、单分片准备、公网校验和取消规则。预览准备与下载任务共用路由策略，但不直接共享下载任务的续传状态。

## 目标与修复范围

解析结果封面提供原生视频预览，支持声音、暂停、进度拖动、全屏及移动端内联播放。

2026-10-20：预览升级为视频模块公共能力，所有解析平台共用入口，不再按域名或 MP4 扩展名限制。支持嗅探单源、音视频组合、普通 yt-dlp 格式 ID、HLS 与 DASH 点播，以及 WebM、FLV 等本地可解码媒体。按媒体能力选择 Range 代理、分片合流或完整文件准备，优先提前播放。音轨必须经过检查；不满足提前播放条件时使用原有完整 H.264/AAC MP4 流程。

“公共能力”表示平台共用，现有登录、账号及记录归属校验保持有效。解析成功并不保证源站始终可访问；签名过期、源站拒绝访问、DRM、直播、超时及资源超限均显示具体失败状态，不隐藏入口或假报播放成功。本文保留原文件路径，避免破坏已有文档链接。

## 用户行为

1. 所有平台存在视频格式时，封面显示播放按钮，不依据页面域名、格式 ID 前缀或容器扩展名关闭入口。普通 yt-dlp 格式按所选格式预览；嗅探线路优先解析器提供的完整音视频组合。下拉框继续控制下载格式。
2. 点击后显示“正在准备音视频”及取消按钮，每 300ms 查询准备状态。分片输出可播放后每 2 秒监测后台状态，输出完成后停止；取消后停止所有轮询。若预览使用其他完整线路，显示“预览使用完整音视频线路”。
3. 可播放后显示带 `controls`、`playsinline`、`preload="metadata"` 的原生播放器，使用原封面为 poster，不强制静音或自动播放。代理及完整文件支持 Range 跳转；生成中的分片仅保证连续播放，完整输出完成后支持任意合法 Range。浏览器拒绝快速路径时自动取消旧会话，并且只回退一次完整文件准备。
4. 只有视频且没有可用音频时，显示“当前源仅含画面，没有可用音频。”；用户选择“继续无声预览”或再次点击中央播放按钮后播放。
5. 配对音频下载失败、缺少音轨或合流失败时，报告失败，不以无声视频代替成功的完整预览。
6. 切换格式、视频、重新解析、返回音乐中心、离开页面或卸载组件时，停止轮询并取消旧会话。旧异步结果不得覆盖当前视频；迟到的创建响应须释放其会话。
7. 历史记录尚未加载格式时也显示入口。点击后先播放服务端已下载的 MP4/WebM，再查询有效的完整预览缓存；二者均不可用时刷新格式并获取在线源。明确仅含音频的格式不提供视频预览。
8. 预览失败时，在视频信息区显示具体原因与“重试播放”按钮，错误不覆盖封面或中央播放按钮。TLS 中断、代理不可用、超时和连接中断分别提示，不统一替换为“准备音视频失败”。
9. 点击预览、准备、取消、失败重试及兼容回退均不得修改解析结果的封面、标题、下载格式列表或当前下载选择；播放器 poster 使用原封面。预览可以使用独立的音视频组合及刷新后的有效地址。

## 来源选择与准备

- 优先级统一为：服务端已下载文件 → 已完成且有效的预览缓存 → 在线源。下载文件从当前记录的已完成任务恢复，沿用 `/api/files/{filename}` 的账号和来源权限校验；存在在线格式也不触发重新解析。浏览器拒绝下载文件或文件已丢失时，本次播放跳过该文件并继续后续来源，不循环重试。
- 已保存到用户电脑与服务端已下载是不同状态。现有“已保存”仅记录浏览器保存成功，不保存读取授权，也不保证本机文件仍存在；不据此创建本机播放地址。
- 缓存仅保存已完成并经过音视频检查的本地 file/fragmented 输出；不缓存 proxy、生成中的分片或失败输出。按账号、解析记录、规范页面和预览格式隔离；历史记录只保留 `saved:<序号>` 时允许使用同记录同页面最近完成的缓存。明确格式选择不匹配则视为未命中。
- 缓存命中先验证当前账号、记录归属、页面关系及平台权限，再创建独立临时会话；不依赖已过期的在线解析缓存，不重新提取或下载。取消当前会话只释放其引用，保留缓存供下次播放；记录删除和账号清理同步撤销会话并删除缓存。缺失、过期或无法读取时继续在线源；命中后文件失效或浏览器拒绝播放时仅自动回退一次完整文件准备，并跳过缓存。
- 页面不设置平台白名单；校验登录账号、解析记录与页面关系。
- 获取在线源时，`sniff:`、`sniffpair:` 及普通 yt-dlp 格式 ID 均须与当前账号该页面的解析缓存完全匹配。嗅探优先使用解析器已经建立的完整组合，不自行猜测或拼接音频。
- `douyin-public` 沿用专用公开解析入口，再进入同一媒体能力检查和准备流程。
- 普通格式 ID 在后台使用现有 yt-dlp 平台适配器重新获取媒体；保留格式选择中的音视频组合规则，分别下载视频、音频，进入统一检查流程。解析与下载失败不会创建普通下载任务或写入下载目录。
- 组合的两个地址均须合法。`.m3u8`、`.mpd`，以及通过响应 MIME 或文件头发现的播放清单使用相同点播准备入口，不受错误的 MP4 标注影响。
- 请求头复用平台解析配置，Referer 为当前页面；B站、YouTube、抖音等 Origin 按各自平台设置，不向其他平台发送固定抖音 Origin。
- 路由复用平台网络策略：原生提取器下载遵守解析配置中的 `proxy=""`，国内平台对应会话关闭环境代理继承；其他平台沿用现有环境路由，不修改系统代理设置。
- 可恢复的网络中断最多尝试 3 次，间隔 0.4/0.8 秒。单源文件读取中断从头重试，原部分文件覆盖，已读取字节仍累计计入 1 GiB 总限额；原生提取器的 GET/HEAD 建连同样有限重试，每次重新执行公网校验与请求计数。POST、证书校验失败及业务/媒体错误不自动重试；保持证书校验，不修改代理线路。每次尝试和等待后检查取消、有效期及准备期限。
- 清单、分片、密钥及提取器 HTTP 请求均使用服务端原生网络下载，每次请求及每次重定向校验公网 HTTP/HTTPS 地址。跨主机重定向移除显式 Cookie/Authorization，保留 yt-dlp 站点 Cookie 管理。拒绝私网、文件协议和外部下载器。
- HLS、DASH 使用 yt-dlp 原生下载器；HLS 必须为有结束标记的点播清单，无法原生处理的清单明确失败，禁止偷偷交给 FFmpeg 读取远端 URL。FFmpeg/ffprobe 只处理本地输入。
- 完整文件路径由 ffprobe 检查视频轨、音频轨、时长和编码。H.264 且像素格式为 yuv420p/yuvj420p 时复制视频，其他可解码视频转 H.264/yuv420p；AAC 音频复制，其他可解码音频转 AAC。显式 `-map` 选择视频和配套音频，使用 `+faststart`。
- 完整文件路径先写 `.part`，复查视频轨、预期音频轨及有效时长，再原子改名为 `preview.mp4`。各路径发布可播放状态前均再次验证关联解析记录。

### 预览刷新与下载状态隔离

- 预览不调用会更新下载状态的 `prepareFormats()`。历史格式过期时，现有 `POST /api/videos/records/{record_id}/formats?force=false` 响应仅保存在本次预览请求内，用于匹配可用播放格式，不替换页面的 `parseResult`，不更新 `selectedFormat`，也不将下载格式标记为已刷新。
- 优先按原格式 ID 匹配；历史 `saved:<序号>` 或已变更的签名 ID 按容器、视频轨属性、清晰度和标签匹配，不能依赖列表顺序或仅凭重复标签选第一项。预览仍沿用完整音视频组合优先规则；其内部格式变化不回写下载下拉框。
- 用户实际下载且需要刷新格式时，只合并新的 `formats`，保留当前封面、标题、作者、时长、页面和记录 ID。按请求完成时的当前下载选择匹配新格式 ID；原先的“自动选择最佳格式”保持空选择。原选择已不存在或无法唯一匹配时，提示“原先选择的下载格式已失效，请重新解析并选择格式。”，不创建其他格式的下载任务，不替换原列表。
- 历史视图中的空 `selected_format` 表示明确选择自动格式，恢复时不得用第一项替代；未保存该字段时才沿用原来的默认规则。
- 刷新期间切换下载格式或取消预览须中止本次预览刷新；切换记录后迟到结果不得创建旧记录的预览，也不得修改新记录。下载和预览各自维护刷新状态。
- 本次仅调整前端状态使用方式，沿用已有 API。MySQL 无表、列、JSON 结构、索引、外键或关系变更，完整表结构沿用现有规格，无迁移、回填或数据库回滚。Redis 无新增或修改 key，既有模板、值结构、类型、TTL、读写、失效及一致性规则保持原规格。回滚仅恢复前端逻辑，无需清理下载文件、业务记录或缓存。

### 快速播放路径

- 单源 MP4：必须支持合法 206 范围响应。有界读取 MP4 元数据及首部样本，本地 ffprobe 确认 H.264/yuv420 和 AAC（或确实无音轨）后，以 `delivery=proxy` 提供原媒体的认证 Range 代理，不等待完整文件。元数据 moov 最多 4 MiB、额外首部样本 64 KiB、顶层盒扫描最多 32 个；快速元数据探测预算为 8 秒，受现有单次 IO 超时约束，不符合条件即走原准备流程。
- 分离 MP4：两个源各自检查轨道、时长。尾部 moov 使用原始合法 Range 读取并调整 stco/co64 偏移，将本地管道输入改为先提供 moov；不修改上游地址。FFmpeg 只读取本地管道，输出分片 MP4；兼容轨道复制，必要时转码。
- HLS/DASH、普通格式 ID：继续由受公网校验的原生提取器与下载器读取清单、密钥和分片。原生下载文件一边写入，一边通过本地管道提供给 FFmpeg，输出 H.264/AAC 分片；选中的视频与音频可各使用一个独立 HTTP 会话并行输入，每条轨道仍为单分片顺序下载。输出首个完整 moof/mdat 后检查音轨，再发布可播放状态，不等待全部分片下载完成。
- 管道源不支持顺序解码时，等待已有输入下载结束后复用本地文件准备，不重复下载同一份已完成输入。显式 `force_prepare=true` 可直接进入完整文件流程。
- 分片模式 `ready` 表示已有可播放片段，`complete=false` 表示后台仍在生成。输出中断改为 failed，前端展示具体原因；不得把首次发布 ready 当作整个后台任务成功。后台准备仍受 300 秒、1 GiB 输入、4 GiB 磁盘限额约束，正在编码或仍有原生下载线程的任务继续占用准备名额。
- Windows 使用可取消的本地命名管道，POSIX 使用本地 FIFO。FFmpeg 协议白名单仍为 file/pipe，不直接访问 HTTP、清单或源签名 URL。取消、账号清理和记录删除会中断输入与媒体工具，清理等待读取引用和输入线程退出。
- `ready/total/metadata` 毫秒值（适用时）保存在当前预览的 `timings_ms`；浏览器在 loadeddata 记录 `performance.measure('video-preview:first-frame')`。上述指标不包含签名 URL、Cookie 或代理凭据。

## 统一解析与性能预算

- 所有平台共用 `parse_runtime` 调度、账号隔离缓存、并发去重、等待预算与计时；差异只在 `parse_adapters`。一般来源依次使用提取器、静态页面、浏览器；直链使用轻量直链适配器。抖音适配器复用已有账号验证会话，B站适配器自行管理 API/网页备用与精确分 P；主流程不重复调用已经失败的浏览器路线。
- 每个规范 URL 与账号的普通/强制刷新请求分别去重，只共享元数据提取，返回模型独立复制；每个 HTTP 请求仍建立自己的历史记录。强制刷新递增当前缓存代次，旧提取任务不得覆盖新一代结果。不同账号不共享带签名的结果。当前单进程最多 4 个未退出的提取任务，不无限排队。
- 解析等待预算为 25 秒，超时返回 504；正在 IO 中的线程在受限操作退出后释放槽位，超时结果不得重新发布成功缓存。提取器 socket timeout 最多 6 秒，元数据重试为 0；静态 HTML 为连接 3 秒、读取 5 秒、最多 4 MiB，剩余预算不足时缩短超时。浏览器导航最多 8 秒、嗅探最多 8 秒，每 200ms 检查资源和预算；源信息齐全即提前返回。
- 预算限制元数据提取等待，不承诺 DNS、数据库写入及操作系统调度均能精确在 25 秒结束。前台响应不等待整部媒体下载、ffprobe、合流或转码。
- 标题和格式就绪后返回，封面保留原图片代理地址供页面按需读取。最多 2 个后台封面任务；繁忙时跳过缓存，不阻塞解析。后台检查账号与记录仍存在，只更新既有封面字段；已删除记录不得重建。封面缓存失败不改变解析成功状态。
- `/api/parse` 返回 `Server-Timing`，包含适用的 cache/extractor/html/browser/public_api/direct/resolve/history/total 毫秒值；阶段日志记录 stage 与 duration_ms。缓存命中时不会重跑提取器；值结构和签名 TTL 沿用原规则。

## 格式元数据兼容

`FormatInfo` 新增可选 `has_video: boolean | null`，默认 null。普通 yt-dlp 格式按 `vcodec` 填写；前端排除明确为 false 的音频格式，旧缓存缺少该字段仍可使用。单文件直链提取结果没有 `formats` 数组时，从自身构造格式候选。现有下载格式 ID、接口路由、原生播放器及字幕时间跳转保持兼容。

## API

### POST /api/previews

请求保持兼容：

```json
{
  "url": "https://www.douyin.com/video/123",
  "format_id": "sniffpair:<编码后的视频地址>|<编码后的音频地址>",
  "parse_record_id": "record123"
}
```

可选 `force_prepare: boolean` 默认为 false；为 true 时跳过下载文件优先、预览缓存和快速路径，用于浏览器兼容回退。为 false 时，后端在解析在线源前也尝试复用同记录、同格式的完整缓存。其余参数、账号归属及来源匹配校验相同。

准备响应：

```json
{
  "preview_id": "<token>",
  "status": "preparing",
  "status_url": "/api/previews/<token>",
  "preview_url": null,
  "expires_in": 600,
  "has_audio": null,
  "message": "正在准备音视频",
  "error_code": null,
  "alternate": false,
  "delivery": "file",
  "complete": false,
  "timings_ms": {},
  "reused": false
}
```

### GET /api/previews/{token}

响应字段同创建接口。状态为 `preparing / ready / failed`。`ready` 才返回 `/api/previews/<token>/content`；`has_audio` 来自当前路径的轨道检查，分片路径在完整输出后再次确认。失败响应保留可展示的中文信息和错误码，不包含源签名地址、工具日志或本地路径。

`delivery` 为 file/proxy/fragmented；旧会话缺少时按 file。`complete` 缺少时按 true；分片 ready/false 时 has_audio 来自首个有效输出片段检查，完整输出后再次检查并发布 true。`timings_ms` 缺少时为空对象，不影响旧客户端。

新增可选 `reused: boolean` 默认 false；缓存复用响应为 true，delivery=file、complete=true，其余状态及内容 URL 契约不变。前端据此在缓存无法播放时只回退一次完整准备。

### POST /api/previews/reuse

在刷新历史格式之前查询完整预览缓存，请求为 `{ "url": "https://example.com/watch/123", "parse_record_id": "record123", "format_id": "720p" }`。url 和 parse_record_id 必填，format_id 可省略；省略时使用同记录同页面最近完成的缓存。命中返回标准 PreviewResponse，未命中返回 HTTP 200 与 JSON null，不创建下载或准备任务。非法页面关系、记录归属或平台权限仍返回原有 4xx，不能将权限失败当作未命中。

### GET /api/previews/{token}/content

- 全部访问验证账号、关联记录及会话有效期；file/fragmented 另校验本地文件存在性，proxy 校验远程响应。
- 未准备完成或准备失败返回 409；文件已清理返回 410；未知或不属于当前账号返回 404。
- 完整文件返回 `video/mp4`；支持单个合法 bytes Range，返回 206 及 Content-Range、Content-Length、Accept-Ranges。多段、非法或超出文件范围返回 416。
- 响应 `Cache-Control: private, no-store`。每次读取持有文件引用，在响应完成或断开后释放，清理任务不得删除仍在读取的文件。
- proxy 模式按原始 Range 转发，由服务端校验每次连接与重定向；最多 4 个同会话并行读取，输入字节计入会话限额。无效内容返回 502，越界范围返回 416。
- fragmented 且 complete=false 时，仅接受无 Range 或 `bytes=0-` 的顺序读取，200 分块响应随文件增长输出；其他范围返回 416。complete=true 后使用普通文件 Range 响应。断开、取消或准备失败时停止输出并释放引用。

### DELETE /api/previews/{token}

验证归属后取消任务、删除会话 key、终止正在执行的媒体工具并清理文件；成功返回 204。准备中的网络读取通过超时及取消检查退出。

### 错误与限制

- 422：音频专用格式、非法媒体地址或无效格式。
- 404/410：解析结果、会话或源过期，记录已删除，文件不存在。
- 429：服务已有两个准备任务，或该用户已有一个准备任务；取消后尚未退出网络读取的任务仍占用名额，避免重复取消绕过并发限制。
- 503：创建会话时 Redis 不可用。
- 后台失败码包括 `timeout / quota / size / upstream / tool_missing / video_codec / audio_missing / media_invalid / output_invalid / prepare_failed / cache / interrupted / cancelled / live / drm / manifest / protocol / network_tls / network_proxy / network_timeout / network_connection`。网络错误展示固定中文信息，不回显签名 URL、代理凭据或底层异常原文。
- 准备最多 300 秒，视频加音频输入总量最多 1 GiB（原生提取器/分片下载同时累计页面、清单及密钥读取字节）；单次无界元数据读取最多 16 MiB。全部临时文件（含输入、输出和进行中文件）最多 4 GiB。超限失败并清理，不无限排队。

## MySQL 数据明细

无新增或修改表、字段、索引、外键及关系，无新增持久化预览记录。继续验证现有解析记录归属，预览为可重建临时资源。可选 `has_video` 随既有解析结果 JSON 保存，不增加数据库列，旧 JSON 缺少字段按 null 处理，因此无表结构迁移、历史数据回填或 SQL 回滚。

## Redis 数据明细

复用现有 key，不新增索引 key：

- 模板：`videodream:video:preview:{user_id}:{token}`。
- 示例：`videodream:video:preview:42:abc_123`（示意 token；实际使用安全随机长令牌）。
- 类型：String；JSON 值的完整 v2 结构如下。

```json
{
  "version": 2,
  "user_id": 42,
  "parse_record_id": "record123",
  "status": "preparing",
  "source_kind": "pair",
  "referer": "https://www.douyin.com/video/123",
  "media_url": "<视频、一体源地址，或 extractor 来源的视频页面地址>",
  "audio_url": "<配套音频地址>",
  "file_id": null,
  "has_audio": null,
  "duration": null,
  "error_code": null,
  "message": "正在准备音视频",
  "worker_id": "<进程及随机实例标识>",
  "created_at": 0,
  "expires_at": 0,
  "alternate": false,
  "delivery": "file",
  "complete": false,
  "timings_ms": {},
  "reused": false
}
```

本次性能优化在同一个 v2 JSON 中增加三个可选字段：`delivery: "file" | "proxy" | "fragmented"`、`complete: boolean`、`timings_ms: {"metadata"?: number, "ready"?: number, "total"?: number}`（毫秒）。新建会话默认 file/false/{}；旧会话按 file/true/{} 读取。proxy 的 file_id 为空，fragmented 的 file_id 仍为安全 token。临时更新始终使用原 `SET XX EX`，不新增 key 或索引。

文件复用优化另增加可选 `reused: boolean`，缺少按 false；复用会话值为 true，`source_kind=cache`、`media_url=规范页面地址`、`audio_url=null`，不保留原签名 URL。其余字段沿用完整文件会话。复用会话在同一现有 key 模板写入，每个播放器单独 token，TTL 为原缓存剩余秒数（最长 1800 秒）；读取或复用不延长到期时间，DELETE 只删除当前会话 key。缓存清单保存在本地，不新增 Redis key、索引或解析缓存字段；已过期的解析缓存不影响通过权限校验的本地文件复用。兼容旧客户端忽略 reused，旧会话按原 TTL 失效。

- `source_kind` 为 `single / pair / extractor / cache`；extractor 来源的 `media_url` 为原视频页面，`audio_url` 初始为 null；所选格式 ID 只由当前进程内任务持有，重启后沿用 preparing→failed/interrupted 规则，不尝试恢复未知的下载选择。cache 为已完成文件复用，见上述兼容规则。
- `file_id` 仅就绪时为服务端生成的 token，不接受客户端路径；`duration` 为有效秒数，`has_audio` 为布尔值，准备阶段两者为 null。
- 准备阶段 TTL 为 `min(600 秒, 两个源的剩余有效期)`，沿用源签名有效期的安全余量。
- 就绪后 TTL 为 `min(86400 秒, max(1800 秒, ceil(视频时长)+600 秒))`。本地文件就绪后不依赖 CDN 签名寿命，13 分钟视频可正常完整预览。
- proxy 就绪 TTL 使用同一时长公式，并取媒体已知签名剩余有效期的较小值（安全余量 15 秒）；未识别到签名到期时间时使用时长公式，不向客户端暴露媒体 URL。分片首次可播放及全部完成时发布对应租期，GET/媒体读取不延长 TTL。
- 创建写入初始值，状态变化写入同一个 key；GET 读取，DELETE/记录删除/账号取消删除。查询和读取不延长 TTL。
- file 就绪必须在输出验证、原子改名之后发布；proxy 在有界轨道检查后发布，fragmented 在完整片段与音轨检查后发布。状态更新使用 Redis `SET XX EX`，已删除或过期的 key 不得被工作线程重新创建。写入失败时清理输出并取消任务。
- 读取还校验 MySQL 记录归属与删除状态；未知/其他账号的 token 不泄露信息。
- 服务重启后，旧实例的 preparing 会话改为 failed/interrupted；就绪会话可在 Redis 和本地文件仍有效时继续读取。
- 新实例也将未完成的 fragmented 会话标记为 failed/interrupted；已完成文件和有效 proxy 元数据可继续使用。回滚前须取消并清理新增 proxy/fragmented 会话及对应文件，防止旧代码将 proxy 误作本地文件；解析缓存无结构变化，无需清理。
- 兼容无 `version=2` 的旧会话，保留旧代理读取直到其原 TTL 到期。新增前后端需配套部署。
- 未认证的直接单元调用保留进程内会话以便测试；实际 HTTP 路由受现有认证中间件保护。

解析缓存仍使用 String/JSON：`videodream:video:parse:{user_id}:{sha256(normalized_url)}`，示例 `videodream:video:parse:42:<64位URL哈希>`。值为完整 ParseResponse（不含 record_id）：`title / thumbnail / duration / uploader / webpage_url / formats`；formats 每项字段为 `format_id / label / ext / resolution / filesize / has_video`。本次仅新增可选 has_video，默认 null；TTL 仍为 `min(600 秒, 已知嗅探源签名剩余有效期)`。成功解析或刷新格式写入，创建预览只读验证，强制重新解析、账号清理或到期失效。缓存写入失败不会扩大预览权限，须重新解析；旧字段兼容无需迁移。

## 文件与生命周期

目录：`.run/video-previews/{token}/`。输入、工具输出及 `.part` 在准备结束后删除；只保留 `preview.mp4` 和仅含用户标识、认证标记、到期时间的 `lease.json`。

完整文件缓存另存为 `.run/video-previews/_cache/{sha256(账号、记录、页面哈希、格式哈希)}/preview.mp4` 与 `manifest.json`。清单完整字段为：version（整数 1）、user_id（整数）、parse_record_id（字符串）、page_hash/format_hash（SHA-256 字符串）、size（字节整数）、has_audio（布尔）、duration（秒数）、alternate（布尔）、created_at/expires_at（Unix 秒），以及来源受限时保留的 access_scope/source_platform 和 route_revision 字符串。复用时沿用当前平台权限及代理版本校验，代理配置变化后旧版本缓存不命中。清单不保存 Cookie、源签名 URL、代理地址或用户电脑路径。

缓存到期时间为首次完整输出时 `min(会话到期时间, 当前时间+1800秒)`，查询和复用不延长。总缓存最多 512 MiB、128 项，超限优先清理旧项；单文件超过上限直接跳过缓存。完成时和每 60 秒清理过期项，缺失文件及中断清单按未命中并清理。缓存和新会话通过同磁盘硬链接复用不可变输出；文件系统不支持硬链接时跳过缓存，继续原流程，不为缓存复制大文件。每个会话持有独立文件引用，移除缓存目录不影响正在播放的会话；准备空间统计仍受 4 GiB 限额约束。

清理器每 60 秒运行，清理取消、到期或 Redis key 已失效的会话；正在读取的文件等待引用归零。取消及记录删除也主动触发清理。重启后按 lease 和 Redis 核对孤立文件；无 lease 的中断输入保留不超过 300 秒后清理。服务关闭取消未完成工具进程，账号停用等取消回调同步撤销该账号预览。

统计临时空间时跳过扫描中已被原生下载器重命名或删除的文件，其他磁盘错误仍按失败处理。管道消费失败时主动停止原生输入；阻塞网络读取在有界超时后退出，退出前继续占用准备名额并保留输入文件，避免删除正在使用的文件。

任务并发控制适用于当前本地单进程服务。多实例共享准备任务和磁盘需要另行设计，不将进程内锁当作分布式锁。
